## Design Context

### Users

API consumers, developers building agents, and API providers. The existing product serves two workspaces: clients discover services, inspect manifests, buy access and make calls; providers publish APIs and manage revenue. Keep both paths visible and let people browse before connecting an identity.

### Brand Personality

Technical, premium, open. The creator requested “web3 + premium + orange + api stuff”, using Arkiv, Arkiv documentation, and Supabase as references. The interface should feel dependable and inviting, with the warmth of the APIritivo name and the precision of a developer tool.

### Aesthetic Direction

Dark by default, continuing the existing app theme. Warm charcoal, off-white text, and a solid orange signal. Manrope for interface and display text; JetBrains Mono for technical content. Large, tightly spaced headings; generous section spacing; fine borders; compact controls. The default theme is an implementation assumption, not a confirmed preference for excluding light mode.

Use Arkiv's editorial hierarchy and indexed sections, its docs' technical clarity, and Supabase's restrained product surfaces. Translate those patterns into APIritivo's own components. Source details and implementation guidance live in `docs/design-system.md`; `/design-system` is the component reference.

### Design Principles

1. Make the next action obvious. Use orange for primary actions and emphasis; reserve green and red for meaningful state.
2. Put useful API information first. Keep code readable, references copyable, and implementation detail inside inspectors.
3. Use quiet surfaces. Group related content with spacing and fine borders; interactive surfaces alone receive hover emphasis.
4. Design every state. Include loading, empty, error, disabled, focus and reduced-motion behavior. Keep navigation usable at narrow widths.
5. Keep the data honest. Example manifests are labeled illustrative. Counts and connection states come from actual application state.
