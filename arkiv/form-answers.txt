3) HOW TO REPRODUCE MISSION 02 — BUILT TO EXPIRE

The purchased duration is the entity's lifetime. When it lapses the API key stops working, the pass leaves "My passes", the sale receipt stays.

Code
  write: packages/arkiv/src/server.ts L228-249 — pass with ExpirationTime.fromSeconds(accessSeconds), sale permanent, one executeBatch
  read (same query before/after): packages/arkiv/src/index.ts L165 getAccessPass, L245 verifyAccessPass; used by every gated call via apps/web/lib/server/access.ts. "Not found" = no access. No delete, cron or revoke anywhere.
  durations: packages/shared/src/service.ts L43 (30 s … 1 year, even seconds because Arkiv counts 2-second blocks)
  UI: apps/web/components/passes-view.tsx L28 (countdown -> "Expired"); tests in apps/web/lib/pass-timing.test.ts

Steps (~3 min)
  1. bun install && bun dev (README "Quick start"); follow docs/JUDGE-WALKTHROUGH.txt steps 1-4, pick "30 seconds" as access duration when publishing.
  2. Buy the pass, copy the key <passKey>.<secret>, open https://data.arkiv.network/?q=$key = key(<passKey>)&chain=tiramisu
  3. bun tools/call-service.ts <serviceId> "<passKey>.<secret>"  -> 200
  4. Wait 40 s, run the identical command -> 403 "Access pass not found on Arkiv or expired." Reload the explorer query -> empty. "Sales" still shows the receipt with the vanished pass_key.

Known limitations: no video timestamps yet; shipped demo services sell 7-day passes, so use a fresh 30-second listing; expiry block estimated ±1 block; access checks are on-demand reads, no WebSocket subscription in this build.
