# CLAUDE.md — APIritivo (ETH Rome 2026)

Read `README.md` first. This file holds the rules that are not obvious from the code.

## What it is

Machine-readable service marketplace. Identity = Swarm ID for everyone (provider and client), client payments = browser wallet, technical manifests = Swarm, registry = Arkiv, payments = USDC on Avalanche Fuji through `contracts/src/APIritivoPayments.sol` (deployed on Fuji; direct transfer only when the contract address is empty).

Monorepo (Bun + Turbo): `apps/web` (Next 15, Tailwind v4), `packages/shared` (Zod schemas), `packages/swarm`, `packages/arkiv`, `packages/payments`, `packages/ens` (read-only ENS), `tools` (demo check), `contracts` (Foundry).

## Non-negotiable rules

- **Never invent SDK methods.** Inspect the `@snaha/swarm-id` and `@arkiv-network/sdk` types in `node_modules/@snaha/swarm-id` and `node_modules/@arkiv-network/sdk` (Bun's hoisted layout; install only with `bun install`, never pnpm or npm) before touching the adapters.
- **Vendor SDKs stay inside `packages/*`.** React components only see `ArkivService`, `ServiceManifest`, `AccessPass`, `Sale`, `SwarmConnectionInfo`, `Signer`.
- **Publish order:** build manifest → upload to Swarm → `manifestRef` → Arkiv entity. Never write Arkiv first.
- **Arkiv attribute names are snake_case** (`entity_type`, `service_id`, `provider_id`, `manifest_ref`, `price_usdc`, `access_seconds`, `payout_address`, `buyer_id`, `buyer_address`, `tx_hash`, `paid_usdc`, `chain_id`, `pass_key`, `secret_hash`, `ens_name`). The chain rejects uppercase letters even though the SDK's local validator accepts them. Always go through `ATTR` in `packages/arkiv/src/entity.ts`.
- **Arkiv links:** entities → Data Explorer via `arkivEntityUrl` / `arkivOwnerUrl` (`https://data.arkiv.network/?q=…&chain=tiramisu`); tx hashes and GLM balances → Tiramisu block explorer via `arkivTxUrl` / `explorerUrl`. Never hand-build explorer URLs in components.
- **ENS is read-only.** The app never writes ENS records. Every displayed EVM address goes through `AddressLabel` (`components/address-label.tsx`, reverse lookup via `useEnsName`, hex in the tooltip); fields that take a recipient go through `useResolvedRecipient` (`lib/use-ens.ts`), which accepts `0x…` or a `.eth` name and resolves it, and the operation always uses the resolved address. Never `slice` an address for display or send to a raw ENS string. A linked name is accepted by `POST /api/services` only when `addr(name)` resolves to the payout wallet (`@apiritivo/ens` `resolveEnsAddress`); records `com.apiritivo.service` and `contenthash bzz://` are set by the provider in the ENS app and verified client-side. Chain from `NEXT_PUBLIC_ENS_CHAIN` (sepolia default). Sepolia is ENSv2 beta: `apiritivo.eth` is registered by the writer and resolves through our own `APIritivoResolver` (0xe647…5a50) because the shared PublicResolverV2 rejects writes. Records are written only via `tools/ens-register.ts` (writer key). Do not attempt subname writes without documented registry ABIs.
- **Service listings are permanent** (`ExpirationTime.permanent()`). Only `access_pass` entities expire; `sale` receipts are permanent so revenue survives.
- **Swarm manifest = technical only** (`v`, optional `endpoint`, `operations`). Name, description, category, price, duration, payout wallet live on Arkiv.
- **Swarm uploads:** pass `subsidisedGatewayUrl` (same value the official Swarm ID demo uses) and never `pin: true` (`Swarm-Pin` is not on the gateway's CORS allow-list → "Failed to fetch"). Direct `POST <gateway>/bytes` is the fallback.
- **Swarm ID iframe** stays mounted once in `#swarm-id-frame` inside the sign-in dialog. Open the dialog from the app, then let the user click the SDK's own button: its popup must keep the iframe as opener for session handover with partitioned storage. Never recreate the iframe or auto-click its button.
- **Server trust boundary:** `POST /api/services` and `POST /api/access-passes` sign with the app-owned Arkiv writer (`ARKIV_WRITER_PRIVATE_KEY`, server only). **Reads trust only that writer:** every Arkiv query filters by `ownedBy(trustedWriterAddress())` and every parser refuses entities from another owner (`NEXT_PUBLIC_ARKIV_WRITER_ADDRESS`, default = the shipped writer; `getWriterStatus().ownerMismatch` flags a key that does not match). Publishing checks the manifest on Swarm, refuses an existing service id and odd durations (Arkiv counts 2-second blocks). Minting requires `buyerSignature`, a `personal_sign` by the paying wallet over `passClaimMessage(txHash, secretHash, fileKey?)`, verifies the purchased duration, writes pass + sale in one `executeBatch`, and answers 503 (not 402/403) when an RPC is down. The gateway only calls public https endpoints (`lib/server/safe-url.ts`) with capped bodies. Every write route goes through `lib/server/http.ts` (JSON errors, 64 KB body cap) and `lib/server/rate-limit.ts` (per-IP, in-memory). `providerId` from the client is still trusted (hackathon boundary, documented in README). **Pass ownership:** the API key is `<passKey>.<secret>`; the pass stores `secret_hash` (keccak256) in clear and the secret AES-GCM-encrypted in the payload under a key from `derivePassEncryptionKey()` (Swarm ID `deriveAppSecret`). `verifyAccessPass` requires the secret; legacy passes without `secret_hash` are refused. Helpers live in `packages/arkiv/src/pass-secret.ts`, never re-implement them. The provider payout wallet is always the Swarm-derived wallet (not editable); the manifest `endpoint` field and the ENS name are not exposed in the publish form (the gateway falls back to the demo bot; `ensName` stays accepted by the API for tools). **Private files (Swarm ACT):** optional per service; `uploadPrivateFile` / `grantPrivateFile` / `downloadPrivateFile` in `packages/swarm` wrap `actUploadData` / `actAddGrantees` / `actDownloadData`. Grants happen in the provider's browser and are recorded as `grant` entities via `POST /api/grants` (newest grant = live history ref). Only the publisher can grant; never try to grant from the server. The service page is descriptive only, bought or not: no Try API console, and `PrivateFilesPanel` in `summary` mode shows only the file name and size (no lock state, request, refresh or download). Try API (`BotConsole`) and the file download (full `PrivateFilesPanel`) live under each pass in My passes (`PassDetails`). The publisher still sees the full file panel on their own service page. The Client account menu never offers the ENS primary-name form (`setPrimaryName` stays unused by the app).
- **Contract is deployed on Fuji** at `0x4e98f464dc8c667e3b0fd3092e0f2d4585702fa3` (owner = Arkiv writer `0x4016…c09C`, fee 0). Redeploy only if the user asks, via `contracts/deploy-fuji.sh`. `NEXT_PUBLIC_PAYMENTS_CONTRACT_ADDRESS` empty = direct-transfer mode; a `NEXT_PUBLIC_*` change needs a `bun dev` restart.
- **Secrets:** `apps/web/.env.local` is gitignored. `.env.example` carries a testnet-only writer key on purpose (user's decision); never put mainnet keys anywhere.
- **Swarm ID is the identity in both workspaces.** The buyer is the signed-in Swarm ID (`buyer_id` = Swarm identity id, `useActiveIdentity()` in `lib/identity.ts`); its `derivePassEncryptionKey()` seals the pass secret and its sharing key (`getGranteeKey()`) is always sent as `buyerPublicKey`, so every sale can be granted a private file. In the Client view the injected browser wallet (`lib/injected-wallet.tsx`, MetaMask/Rabby/Core) is only the payment method: it signs approve/buy and the pass claim (`signPassClaim`); `buyer_address` = that wallet. It is connected only at checkout (`BuyAccess`, "Connect wallet to pay"), never from the account menu or before, and a Swarm ID sign-out forgets it. `useActiveAccount()` combines the two (Client) or uses the Swarm-derived wallet (Provider). The Swarm-derived wallet is derived only in the Provider workspace (`SwarmWalletProvider`); the client only derives the pass encryption key (`passKeyStatus`) and never sees or waits on that wallet. `keyFromSignature` / `PASS_KEY_MESSAGE` in packages/payments are no longer used by the app. Marketplace, service pages, My passes and the provider pages all require a signed-in Swarm ID (`AuthGate`); only home, Docs and the design system are public. Buying also needs the wallet.
- **Role:** client/provider is one localStorage preference per browser (`apiritivo:workspace`), never access control. Switching workspace always goes through `switchWorkspace()` in `lib/session.tsx`: it saves the choice, signs out of Swarm ID when signed in and reopens the sign-in dialog, so every workspace starts with a fresh Swarm ID login. Never change the workspace of a signed-in session without signing out. AppShell hides the other workspace's pages. See UI guidance for navigation rules.

## Quality gate (run before finishing)

```bash
bun typecheck && bun lint && bun test && bun run build   # never `bun run build` while `bun dev` is running: both write apps/web/.next
bun check:fix           # Biome format + safe fixes (biome.json at the root); `bun lint` = `biome check .` then ESLint in apps/web (the only ESLint user)
# CI (.github/workflows/ci.yml) runs the same gate plus `forge test` on every push; keep it green.
bun test:contracts      # Foundry
bun demo:check          # external dependencies
```

Playwright is available in the scratchpad for overflow/console checks (see git history for the scripts). Pages that need Swarm ID login cannot be driven headless; ask the user to verify them in the browser.
